# Phase 5: SEO Pre-Publish Checklist
**For blogs and service page updates | Use before publishing June 1 - Aug 9**

Run through this checklist before publishing each blog post or service page update. Typical completion time: 30-45 minutes per piece. Target: 100% pass rate before going live.

---

## 📋 Pre-Publish Checklist

### 1. METADATA & SEO BASICS

#### Title Tag
- [ ] Title is 50-60 characters (displays fully in SERP)
- [ ] Primary keyword in title (first third preferred)
- [ ] Compelling and click-worthy (user intent clear)
- [ ] No keyword stuffing or duplicate titles
- [ ] Examples:
  - ✅ "How to Hire a Private Chef in Bali | 2026 Guide"
  - ✅ "Private Chef Cost in Bali: Complete Pricing Breakdown"
  - ❌ "Private Chef Private Chef Cost Bali"

#### Meta Description
- [ ] Description is 150-160 characters (fits in SERP)
- [ ] Includes primary keyword naturally
- [ ] Includes secondary keyword if natural
- [ ] Clear value proposition or answer
- [ ] Call-to-action present (optional but good)
- [ ] Example: "Learn how to hire a private chef in Bali. Compare costs, qualifications, vetting tips, and find the right chef for your villa stay."

#### Slug & URL Structure
- [ ] URL is descriptive and keyword-relevant
- [ ] Lowercase, hyphens between words
- [ ] No unnecessary parameters or numbers
- [ ] Consistent with site structure
- [ ] Examples:
  - ✅ `/blog/how-to-hire-private-chef`
  - ✅ `/blog/private-chef-cost-breakdown`
  - ❌ `/blog/article-123`

---

### 2. CONTENT STRUCTURE

#### H1 Tag
- [ ] Exactly ONE H1 on page
- [ ] H1 matches or closely mirrors title tag
- [ ] Keyword present (natural, not forced)
- [ ] Clear and compelling
- [ ] Example: "Complete Guide: How to Hire a Private Chef in Bali"

#### H2 Tags
- [ ] All H2s are relevant and descriptive
- [ ] H2s follow logical flow (scannable outline)
- [ ] No H2s skipped (no H3 without H2)
- [ ] At least 5-8 H2s for 3,000+ word content
- [ ] Secondary keywords distributed across H2s naturally
- [ ] Example flow:
  - H1: "How to Hire..."
  - H2: "What Does a Private Chef Actually Do?"
  - H2: "What Should It Cost?"
  - H2: "Essential Qualifications to Look For"
  - H2: "How to Find & Vet"
  - H2: "The Hiring Process: Step-by-Step"

#### Intro Paragraph
- [ ] First paragraph addresses primary keyword
- [ ] Answers the "why" and "what" for the query
- [ ] 100-150 words, clear hook
- [ ] Natural keyword placement (not forced)
- [ ] Excerpt/snippet works from this paragraph

#### Content Quality
- [ ] Word count meets target:
  - Blogs: 3,000-4,000 words (or target per guide)
  - Service pages: 1,200-1,500 words after expansion
- [ ] Information is accurate and current (2026)
- [ ] Examples and data provided (not generic)
- [ ] Matches search intent (answer the question asked)
- [ ] No thin content or filler paragraphs
- [ ] Readability: Short paragraphs, bullet points for lists

---

### 3. KEYWORD OPTIMIZATION

#### Primary Keyword
- [ ] Appears in: H1, first H2, intro, naturally throughout body
- [ ] Frequency: 1-3 times per 1,000 words (not forced)
- [ ] Variations used: "hire private chef", "hiring", "how to hire", etc.
- [ ] Example: "Complete Guide: How to Hire a Private Chef in Bali" + variations in content

#### Secondary Keywords
- [ ] Secondary keywords distributed in H2s and body
- [ ] Examples for "hire private chef" post:
  - "private chef cost" (link to cost breakdown blog)
  - "chef qualifications"
  - "bali chef vetting"
  - "how much does private chef cost"
- [ ] No keyword stuffing in any section
- [ ] Natural language flow maintained

#### Keyword Placement Checklist
- [ ] Primary keyword in:
  - [ ] Title tag
  - [ ] H1
  - [ ] First 100 words
  - [ ] First H2
  - [ ] Meta description
- [ ] Secondary keyword in:
  - [ ] At least one H2
  - [ ] 1-2 body mentions
  - [ ] Ideally one internal link anchor text

---

### 4. INTERNAL LINKING

#### Link Count
- [ ] Blogs: 5-8 internal links minimum (target 6)
- [ ] Service pages: 3-5 internal links
- [ ] Links are contextually relevant (not forced)
- [ ] No self-referential links
- [ ] Links appear naturally in body text (not only sidebar/footer)

#### Link Quality
- [ ] Each link has descriptive anchor text (not "click here")
- [ ] Anchor text includes relevant keywords when natural
- [ ] Examples:
  - ✅ "Learn how to hire the right chef" (anchor: link to /blog/how-to-hire)
  - ✅ "See detailed cost breakdown" (anchor: link to /blog/cost-breakdown)
  - ❌ "Click here"
  - ❌ "More info"

#### Link Relevance Map
- For Blog #1 (How to Hire), links should point to:
  - /blog/private-chef-cost-breakdown (cost section)
  - /blog/chef-hiring-guide (qualifications)
  - /blog/chef-hiring-guide (hiring process)
  - /chefs (browse chefs CTA)
  - /services/events (related service)

#### Link Validation
- [ ] All links tested and working (no 404s)
- [ ] Links open to correct pages
- [ ] No redirect chains
- [ ] Links are permanent (not ephemeral)

---

### 5. IMAGES & MEDIA

#### Image Presence
- [ ] At least 1 hero image above fold
- [ ] Additional images every 2-3 sections (break up text)
- [ ] Total: 3-6 images for 3,000+ word blog
- [ ] Images are high quality (not blurry or watermarked)
- [ ] Images are relevant to content (not decorative)

#### Image Optimization
- [ ] All images have descriptive alt text
  - ✅ "Private chef plating fine dining dish in Bali villa kitchen"
  - ❌ "image1.jpg" or "photo"
- [ ] Filenames are descriptive and lowercase
  - ✅ "private-chef-bali-kitchen.jpg"
  - ❌ "IMG_12345.jpg"
- [ ] Images are compressed (no >2MB images)
- [ ] Image format is modern (WebP or JPEG, not BMP)
- [ ] Image width is appropriate for context:
  - Hero: Full width or 1200px max
  - In-content: 600-800px
  - Thumbnails: 300px max

#### Image Accessibility
- [ ] Images have alt text describing content
- [ ] Alt text includes relevant keywords naturally (not stuffed)
- [ ] SVG icons have aria-label or title attributes
- [ ] No text embedded in images (screen reader inaccessible)

---

### 6. SCHEMA MARKUP

#### Schema Type Selection
- [ ] Correct schema type selected:
  - Blogs: Article + FAQPage schema
  - How-To posts: HowTo schema + FAQPage
  - Service pages: Service schema
- [ ] Schema syntax is valid JSON-LD
- [ ] Schema is placed in `<head>` or structured inline

#### Article Schema (All blogs)
- [ ] @type: "Article"
- [ ] headline (matches H1)
- [ ] description (excerpt, 100-150 chars)
- [ ] author with Organization name
- [ ] datePublished (ISO 8601 format)
- [ ] image (hero image URL)
- [ ] articleBody (if including full content)

#### HowTo Schema (For how-to blogs)
- [ ] @type: "HowTo"
- [ ] name (article headline)
- [ ] description
- [ ] step array with at least 5 steps
- [ ] Each step has: @type "HowToStep", position, name, text
- [ ] Example: Blog #1 has 6+ HowTo steps

#### FAQPage Schema (All blogs)
- [ ] @type: "FAQPage"
- [ ] mainEntity array with Q&A pairs
- [ ] At least 3 FAQ items
- [ ] Each Q&A has: @type "Question", name, acceptedAnswer with text
- [ ] FAQs answer common follow-up questions

#### Service Schema (Service pages)
- [ ] @type: "Service" or "LocalBusiness"
- [ ] name
- [ ] description
- [ ] provider (Organization)
- [ ] areaServed (Bali, Indonesia)
- [ ] image
- [ ] priceRange (if applicable)
- [ ] aggregateRating (if reviews available)

#### Schema Validation
- [ ] Validate with Google Rich Results Test (search.google.com/test/rich-results)
- [ ] No errors or warnings shown
- [ ] All required properties populated
- [ ] Structured data matches actual page content

---

### 7. CORE WEB VITALS & PERFORMANCE

#### LCP (Largest Contentful Paint)
- [ ] LCP < 2.5s (target) on desktop
- [ ] LCP < 3.0s on mobile
- [ ] Test with Lighthouse (dev tools)
- [ ] If slow:
  - [ ] Compress hero image
  - [ ] Defer non-critical CSS
  - [ ] Check third-party scripts

#### INP (Interaction to Next Paint)
- [ ] INP < 200ms on all interactions
- [ ] Test clicking links, scrolling, form inputs
- [ ] Ensure no janky interactions
- [ ] If slow:
  - [ ] Profile with DevTools Performance tab
  - [ ] Defer non-critical JavaScript
  - [ ] Optimize event listeners

#### CLS (Cumulative Layout Shift)
- [ ] CLS < 0.1
- [ ] No content jumping during load
- [ ] Images have dimensions specified
- [ ] No ads/embeds causing shifts
- [ ] If high:
  - [ ] Add width/height to all images
  - [ ] Reserve space for ads
  - [ ] Avoid inserting content above fold

#### Mobile Responsiveness
- [ ] Test on actual phones (320px, 375px, 768px widths)
- [ ] No horizontal scroll at any viewport
- [ ] Readable text (14px+ font minimum)
- [ ] Touch targets 44x44px minimum
- [ ] Images responsive (max-width: 100%)

#### Page Speed Checklist
- [ ] Google Lighthouse score ≥ 80 (desktop)
- [ ] Google Lighthouse score ≥ 70 (mobile)
- [ ] Core Web Vitals all green in PageSpeed Insights
- [ ] No render-blocking resources (CSS, JS deferred)
- [ ] Images lazy-loaded below fold

---

### 8. CALLS-TO-ACTION

#### CTA Presence
- [ ] At least one CTA above fold (hero section)
- [ ] At least one CTA in body (mid-page)
- [ ] At least one CTA below fold (end of content)
- [ ] Total: 2-4 CTAs per blog/page

#### CTA Quality
- [ ] CTAs are visually distinct (button styling)
- [ ] CTA text is clear and action-oriented
  - ✅ "Book Your Chef"
  - ✅ "Get a Free Consultation"
  - ✅ "Browse Available Chefs"
  - ❌ "Click Here"
  - ❌ "Learn More" (too generic)
- [ ] CTAs link to relevant pages:
  - Hire-related → /booking or /chefs
  - General → /contact
  - Specific → Relevant service page
- [ ] CTA is tracked in GA4 (cta_click event)

#### CTA Placement
- [ ] Hero CTA above fold (visible without scroll)
- [ ] Inline CTAs in relevant sections (after value prop)
- [ ] Final CTA after conclusion (strong close)
- [ ] Sidebar CTAs (if sidebar exists)

---

### 9. CONTENT QUALITY & ACCURACY

#### Fact-Checking
- [ ] All statistics and data are cited or sourced
- [ ] Names and credentials are accurate
- [ ] Pricing information is current (2026)
- [ ] No false claims or overstatements
- [ ] Competitive comparisons are fair and accurate

#### Writing Quality
- [ ] No grammatical errors or typos
- [ ] Consistent tone and voice
- [ ] Clear and concise language (no jargon without explanation)
- [ ] Active voice preferred over passive
- [ ] Logical flow and transitions between sections

#### Depth & Authority
- [ ] Content goes deeper than competitor posts
- [ ] Original insights or data included (not just rehashed)
- [ ] Examples or case studies provided
- [ ] Answers the query completely (user wouldn't need to search further)
- [ ] Demonstrates expertise (not generic guide)

#### Engagement
- [ ] Subheadings are interesting and click-worthy
- [ ] Bullet points used to break up text
- [ ] Short paragraphs (2-4 sentences typical)
- [ ] Varied sentence length and structure
- [ ] Reader can skim and understand key points

---

### 10. TECHNICAL SETUP

#### Meta Tags
- [ ] robots meta tag allows indexing (no noindex)
- [ ] viewport meta tag present (mobile-friendly)
- [ ] charset UTF-8 specified
- [ ] Open Graph tags present (for sharing):
  - og:title
  - og:description
  - og:image
  - og:url
- [ ] Twitter Card tags (optional but good):
  - twitter:card
  - twitter:title
  - twitter:description
  - twitter:image

#### Canonical Tag
- [ ] Canonical tag present and correct
- [ ] Points to self (same URL)
- [ ] No issues with trailing slashes or parameters

#### Mobile Optimization
- [ ] Responsive design (tested at 320px, 375px, 768px)
- [ ] Hamburger menu for mobile (if applicable)
- [ ] Tappable elements (44x44px minimum)
- [ ] No viewport meta zoom restrictions

#### Accessibility (WCAG 2.1 AA)
- [ ] All images have alt text
- [ ] Color contrast ratio 4.5:1 minimum for text
- [ ] Keyboard navigation works (Tab through all links)
- [ ] No keyboard traps
- [ ] Form labels associated with inputs
- [ ] Heading hierarchy is logical (no skipped levels)

---

### 11. GSC & SUBMISSION

#### Pre-Submission
- [ ] Page is live and accessible (no 404)
- [ ] No noindex tag (verified in meta tags)
- [ ] Mobile-friendly (test with Mobile-Friendly Test)
- [ ] No redirects or chains

#### GSC Submission
- [ ] Page URL added to GSC
- [ ] Request indexing in GSC
- [ ] Wait 2-5 minutes for crawl verification
- [ ] Check status in Coverage report after 24-48 hours
- [ ] If not indexed: Check for issues in GSC

#### GSC Monitoring
- [ ] Page appears in GSC coverage (indexed status)
- [ ] Check performance report after 1 week
- [ ] Monitor for crawl errors
- [ ] Monitor for enhancement warnings (schema, mobile)

---

### 12. POST-PUBLISH VALIDATION

#### 24-Hour Checks
- [ ] Page indexed in Google (site: query)
- [ ] Content appears in search correctly
- [ ] Meta title and description display as intended
- [ ] Featured image shows in SERP preview
- [ ] No broken links or images on live page
- [ ] CTAs are clickable and functional

#### 7-Day Checks
- [ ] Page showing in GSC coverage report
- [ ] First organic traffic appearing (if indexed)
- [ ] Average position data in GSC (usually appears day 3-5)
- [ ] No crawl errors related to page
- [ ] Mobile usability shows as "Good" in GSC

#### 30-Day Monitoring
- [ ] Page has received 10+ impressions (if indexed)
- [ ] Page has received 1+ clicks (if indexed)
- [ ] Check bounce rate in GA4 (target <50% for blogs)
- [ ] Check average session duration (target >2 min)
- [ ] Monitor for ranking progress

- [ ] All links tested and working

4. [ ] 3-6 images with alt text

1. [ ] H2 sections added for new content
2. [ ] Primary keyword in new sections
3. [ ] 2-3 internal links added (natural)
4. [ ] 1-2 images for new sections
5. [ ] Update schema (Service or LocalBusiness)
6. [ ] Verify all CTAs still present
7. [ ] Lighthouse check still ≥70
8. [ ] Title/description updated if content changed significantly
9. [ ] GSC resubmit (request reindexing)
