# myCHEF Content Calendar System

## Purpose
Build a repeatable editorial system for Phase 3 content publication so myCHEF can publish one high-intent post per week, balance commercial and brand storytelling, and keep internal linking aligned with service pages.

## Publishing Model
- **Cadence:** 4 posts per month, 1 post per week
- **Word count:** 800-1200 words per post
- **Format:** SEO-first article with one primary keyword, 2-4 secondary variations, and clear CTA
- **Primary CTA:** `Get a custom quote` or `Check pricing`, depending on intent
- **Update rhythm:** Review queue in the final week of each month and roll the next 4 briefs forward

### Weekly Cadence
| Week | Pillar | Job to Be Done | Default CTA |
|---|---|---|---|
| Week 1 | Villa Dining | Capture chef-service and villa-dining intent | `/pricing`, `/calculator` |

## Sitewide Internal Linking Rules
1. Every post links to **1 primary money page** in the first half of the article.
2. Every post links to **1 conversion page** (`/pricing`, `/calculator`, or `/quote`) near the middle or close.
3. Every post links to **2 supporting articles** from the blog archive where relevant.
4. Use descriptive anchors: `private chef in Bali pricing`, `wedding catering in Bali`, `Seminyak private chef service`.
5. Avoid linking multiple times to the same URL unless the second link is a CTA.
6. Add one location link whenever the article mentions Seminyak, Canggu, Ubud, Uluwatu, Sanur, or Nusa Dua.

## Content Optimization Checklist
- Keep **one primary keyword** in the H1, intro, one H2, meta title, and meta description.
- Include **2-4 secondary keywords** naturally in supporting H2s.
- Use **short paragraphs**, concrete examples, and one Bali-specific operational detail per section.
- Add **1 proof element** minimum: named service type, guest size, timing example, or sourcing detail.
- Include **3-5 internal links** and **0-2 external citations** only when they add trust.
- End with a CTA that matches intent: pricing, quote, or related service page.

## Implementation Checklist

### Adding a New Blog Post
1. Open `src/data/sitemap.ts`.
2. Find the `BLOG_POSTS` array.
3. Add a new object with this shape:
   ```ts
   {
     slug: 'blog/your-post-slug',
     title: 'Your Post Title',
     description: '150-160 character summary for search results.',
     date: '2026-06-05',
     content: `<h2>...</h2><p>...</p>`
   }
   ```
4. Keep the slug lowercase and hyphenated.
5. Keep descriptions tight, specific, and search-friendly.
6. Write HTML content with internal links using existing route paths.
7. Confirm the article links to one service page, one conversion page, and one related article.

### Quality Gates
1. **TypeScript:** `npx tsc -b`
2. **Production build:** `npm run build`
3. **Manual review:**
   - Verify slug, title, and description render correctly.
   - Confirm internal links use valid live routes.
   - Check article tone against `.kimi/BLOG_POST_TEMPLATE.md`.
4. **Lint note:** `npm run lint` currently has pre-existing script errors outside this content-calendar task, so treat TypeScript + build as the required release gate unless those script issues are fixed separately.

### GitHub + Vercel Deployment Flow
1. Create/update the content branch.
2. Add the new post inside `src/data/sitemap.ts`.
3. Run `npx tsc -b` and `npm run build`.
4. Commit and push to GitHub.
5. Open a pull request and review the Vercel preview deployment.
6. Verify the article route, metadata, and internal links in preview.
7. Merge to `main` to trigger production deployment in Vercel.
8. After deploy, request indexing in Google Search Console and link the new article from one older post.

## Monthly Operating Ritual
- **Last week of current month:** approve next month’s 4 titles.
- **1 week before publish:** finalize brief from `.kimi/BLOG_POST_TEMPLATE.md`.
- **Publish day:** add post, build, preview, deploy.
- **48 hours after publish:** check indexing, click-through rate, and internal-link placements.
- **Month end:** keep winners, refresh underperformers, and move best-performing angles into service-page copy.
