### 9.1 Location Page Template

Every location page follows an identical structural template. Consistency allows Google to understand the pattern, index pages faster, and rank them for predictable query patterns.

**URL Structure:** `mychef.id/bali/private-chef/[location]/`

The `/bali/` subdirectory signals geo-relevance; `/private-chef/` reinforces topical focus. This two-level nesting supports future expansion (e.g., `/bali/catering/canggu/` follows the same pattern).

**Title Tag Formula:** `[Service] [Location] Bali | [Benefit] — myCHEF`

Keep titles within 60-65 characters. Service keyword first ("Private Chef"), location second ("Canggu"), geographic modifier third ("Bali"), benefit statement last.

**Meta Description Formula:** `Hire a [service] in [Location], Bali. [Location-specific detail]. From Rp 800K/hour. 1000+ happy guests. WhatsApp +62 822-3756-5997.`

~160 characters. Must include service + location combination, unique differentiator, price anchor, social proof, and WhatsApp CTA.

**H1 Formula:** `[Service] [Location] Bali — [Unique Value Proposition]`

The H1 never duplicates the title verbatim. It expands with a benefit-driven phrase unique to that location — "Villa Dining in Bali's Trendiest Beach Town" for Canggu, "Organic Dining in Bali's Cultural Heart" for Ubud.

**Required Content Sections:**

| Section | Purpose | Word Target |
|---------|---------|-------------|
| H1 + Local Introduction | Establish geo-relevance, set the scene | 75-100 |
| Why This Location | Unique local context that differentiates this page | 100-150 |
| What's Included | Service details (chef, cleanup, ingredients) | 75-100 |
| Local Villas We Serve | Name-drop recognizable villa names | 50-75 |
| Pricing | Consistent pricing table across all locations | 50-75 |
| How to Book | 3-step process with customized CTA | 50-75 |
| Local FAQ | 3-5 location-specific questions with schema | 100-150 |
| CTA: WhatsApp Button | Direct conversion element | — |
| Internal Links | Cross-links to related locations and services | — |

Total content target: **500-800 words** of unique prose per page — substantial enough to avoid Google's thin-content penalty, lean enough to produce at scale across 14 locations.

**Schema Requirements:** Each page needs **LocalBusiness** schema with geo-coordinates for the specific area, **Service** schema with the location in `areaServed`, **BreadcrumbList** schema, and **FAQPage** schema on the local FAQ section. The FAQ schema unlocks rich snippet expansion in search results, pushing competitors below the fold.

### 10.2 Post Template and Production Standards

Every post follows this standardized template:

| Element | Specification |
|---------|--------------|
| **Title** | Primary keyword near beginning, benefit-driven, under 65 characters |
| **URL** | `/blog/[category]/[primary-keyword-slug]/` |
| **Meta description** | 150-160 chars, includes primary keyword, benefit, CTA |
| **H1** | Primary keyword included, unique from title tag |
| **H2s** | 4-8 per post, each addressing a sub-topic |
| **H3s** | 0-12 as needed under H2s |
| **Opening** | Hook + primary keyword in first 100 words |
| **Body** | Analytical prose with data, tables, specific examples |
| **Images** | Minimum 3 per post with descriptive alt text |
| **Internal links** | 3-5 contextual links to service/location pages |
| **FAQ section** | 3-5 questions with FAQPage schema |
| **CTA** | WhatsApp click-to-chat button: "Ask About [Topic]" |
| **Schema** | Article schema + FAQPage schema |
| **Word count** | 1,500-2,500 words |
| **Tone** | Expert, helpful, conversational; third person with occasional "we" |

**Production time per post:** 4-6 hours (1h keyword/outline, 2-3h writing, 1h images/schema, 0.5h editing). A single producer can deliver **2-3 posts per week** — all 30 posts within 90 days.
