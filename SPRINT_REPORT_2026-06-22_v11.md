## Audit (data-driven, before touching anything)
Confirmed source of truth = root `/src` (the `app/` dir is a stale duplicate, per run 10). Ran the proven route↔sitemap graph audit and extended it:

- **Routes vs sitemap.** Built the full registered-route set (static `App.tsx` paths + generated `LANDING_PAGE_SLUGS`/`GUIDE_SLUGS`/`BLOG_POST_SLUGS`/`SERVICE_SLUGS`/`MENU_SLUGS`/`AREA_SLUGS`/`MICRO_AREA_SLUGS` + location data). Diffed against `public/sitemap.xml` (151 URLs). After accounting for generated slugs, the only unmatched sitemap entries were the dynamic `/chefs/:slug` (8) and `/journal/:slug` (14) URLs.
- **Dynamic-route validation.** All 8 chef sitemap slugs are defined in `ChefProfilePage.tsx` → resolve. All 14 journal sitemap slugs exist in `JOURNAL_POSTS` (and the sitemap is auto-generated by iterating `JOURNAL_POSTS`, so journal orphans are structurally impossible). **No soft-404s, no orphans.**
- **Thin content.** `JOURNAL_POSTS` carry full rich-HTML `content` (multi-section, internally linked, with images) — not thin.
- **Schema coverage.** `breadcrumbSchema()` is called by 116 files (my first grep was misleading — the helper emits `'@type':'BreadcrumbList'`, so breadcrumb coverage is effectively sitewide). AggregateRating on 21 pages. An `eventSchema()` helper exists but is used by 0 pages — **deliberately left unused**: the events pages are service offerings with no `startDate`, so emitting `Event` schema would generate "Missing field startDate" errors in GSC. Adding it would be a regression, not a fix.

Net: the site's structural SEO is genuinely clean. The one safe, correct, high-ROI gap was inside the journal Article schema.

## The defect
`JournalPostPage` (`src/components/JournalPage.tsx`) emitted, for all 15 single posts:
1. **No `image`** — Google lists `image` as a recommended Article property; absence reduces rich-result eligibility.
2. **`author: { '@type':'Organization', name:'myCHEF' }` hardcoded** — even though 5 of 15 posts have a real person byline (`Adriano`, who also has a live `/chefs/adriano` profile). Weak E-E-A-T authorship signal.

## Changes (commit `4f19feb`, 1 file, +21/−2)
- `image`: extract the first `<img src>` from `post.content`, make it absolute (`${SITE}${src}`); fall back to the site OG image when a post has no in-body image. Always populated.
- `author`: emit `Person` (with `url` → chef profile when known, via a small `AUTHOR_PROFILES` map) for real bylines; keep `Organization` for the in-house `myCHEF Team` byline. Branch via `/team|mychef/i.test(post.author)`.
