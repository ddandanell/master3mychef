## CORRECTION to v4's one open fix
v4 recommended deleting the secondary cost URL's `<url>` block directly from `public/sitemap.xml`. **That is the wrong location** — `public/sitemap.xml` is generated by `scripts/generate-sitemap.ts` from source data, and `CLAUDE.md` forbids hand-editing generated files (a regen would silently revert it).

Re-investigation of the actual data model:
- The "secondary" URL is **not a stray sitemap line** — it is a full, unique blog post defined in `BLOG_POSTS` (`src/data/sitemap.ts:422`, slug `blog/private-chef-bali-cost-breakdown-detailed-2026`), rendered by a 735-line page, and converted to a sitemap URL by `buildSitemap()` (`src/data/sitemap.ts:692`).
- It already self-declares `/blog/private-chef-cost-bali` as its canonical, so Google is **not** treating the two as competing duplicates. ✅

**Therefore this is a content-strategy decision, not a mechanical cleanup, and it needs the owner:**
- Option A (treat as duplicate): remove its `BLOG_POSTS` entry / exclude from `buildSitemap()`, then run `scripts/generate-sitemap.ts` to regenerate `public/sitemap.xml`. Keep the page live via canonical.
- Option B (treat as distinct article): give it its **own** canonical — but that reintroduces "private chef cost bali" cannibalization between the two pages.

Default recommendation: **A**, but only with owner sign-off on which page is primary. Value is minor (a self-canonicalizing URL listed in sitemap) and **cannot deploy** under the current git blocker regardless.
