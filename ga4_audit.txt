3. CODE IMPLEMENTATION — WHAT IS BUILT
════════════════════════════════════════════════════════════════

FILE: src/lib/analytics.ts
  Central event hub. All tracking functions call:
  1. window.gtag('event', ...) — fires to GA4
  2. window.dataLayer.push(...) — GTM fallback, always fires

FILE: index.html (lines 63–101)
  Deferred GA4 bootstrap: loads gtag.js after requestIdleCallback
  (2500ms timeout) or 1500ms setTimeout fallback.
  Also initialises GTM if VITE_GTM_ID env var is set (currently not set).

FILE: src/main.tsx
  Mounts @vercel/analytics (Vercel's own product analytics, separate
  from GA4) and @vercel/speed-insights. These work independently.

EVENTS IMPLEMENTED:

  trackWhatsAppClick(source)      → generate_lead (method: WhatsApp)
    Called from: ServicePage CTA, WhatsAppButton floating button,
    PillarSubPage CTA, StickyMobileCTA, Layout sitewide listener

  trackPhoneClick(source)         → generate_lead (method: Phone)
    Called from: Layout sitewide tel: click listener

  trackPageView(path)             → page_view
    Called from: Layout on every React Router route change

  trackScrollDepth(depth, source) → scroll_depth
    Called from: useScrollDepth hook (25/50/75/90% milestones)

  trackTimeOnPage(seconds, source) → time_on_page
    Called from: useTimeOnPage hook (30/60/120/180s milestones)
    !! Hook defined but NOT imported/used in any page component

  trackEvent('quote_submitted', ...)
    Called from: QuoteFunnel — when user clicks "Send via WhatsApp"

  trackFormStart()                → form_start    [DEFINED, NEVER CALLED]
  trackFormComplete()             → form_complete  [DEFINED, NEVER CALLED]
  trackCTAClick()                 → cta_click      [DEFINED, NEVER CALLED]

SITEWIDE CONVERSION LISTENER (Layout.tsx):
  document.addEventListener('click', ...) captures ALL clicks on:
  - Any a[href*="wa.me"] (WhatsApp links) — fires generate_lead
  - Any a[href^="tel:"] (phone links) — fires generate_lead
  This is a solid catch-all that does NOT require individual component
  instrumentation for WhatsApp/phone clicks.

  Top page: "Private Tutor Near Me · Bali · IB Cambridge IGCSE · 5★"
  This title has 23 views in 7 days but belongs to a tutoring website,
  NOT mychef.id. This means the GA4 property G-W0PQH8ZKTF is receiving

  another site (tutoring business) and that site is still sending hits.
  OR: The property was shared/reused when setting up mychef.id.

  Action required:
  a) Go to GA4 Admin → Data Streams
  b) Check all streams attached to this property
  c) Remove any stream that is not mychef.id
  d) Consider creating a fresh GA4 property for a clean baseline

RED FLAG 2 — discovery_call_form_start EVENT:
  10 occurrences in last 7 days, NOT present in current codebase.
  This event name appears to come from a previous version or a GTM
  container that was active on the site.

  If this came from the tutoring site contamination: explains the
  mismatch between events and mychef.id behaviour.

RED FLAG 3 — ZERO ORGANIC SEARCH SESSIONS:
  Despite active SEO work (sitemaps submitted, pages indexed), GA4
  shows 0 organic search sessions in 7 days. Either the site is not
  yet ranking and receiving clicks, or organic sessions are being
  miscategorised as Direct (common with GA4 when referrer is lost).

RED FLAG 4 — GTM NOT CONFIGURED:
  VITE_GTM_ID is blank. index.html silently skips GTM bootstrap.
  This is fine if GTM is not being used, but if conversion tracking
  was being routed through GTM previously, it would explain gaps.
